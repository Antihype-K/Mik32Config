# Стандарты кода проекта

Выжимка из CLAUDE.md специально для `code-review`-скилла (ось Standards). Полный контекст и обоснования — в CLAUDE.md.

- **Новая существенная логика — в новые файлы** (header/cpp), не внутрь существующих. Минимальные правки в существующих файлах допустимы только для подключения нового модуля.
- **Авторство кода при работе по датащиту/примеру**: каждый блок кода — комментарий простым языком что он делает; каждая строка/тесная группа строк, где значение взято из даташита/errata/вендорного примера — комментарий с точной ссылкой (раздел даташита/errata или путь:строка примера). Никогда не выдуманное значение.
- **Не угадывать полярность/назначение бита регистра**, если оно не подтверждено документом или HAL. Отсутствие уверенности — повод не трогать бит, а не поставить разумное на вид значение.
- **При расхождении реального HAL (`docs/examples/`, установленный SDK) и архитектурного документа — выигрывает реальный HAL.** Расхождение фиксируется в `docs/implementations/`.
- **Эррата приоритетнее даташита** при конфликте — подтверждённое HW-отклонение должно определять workaround в генерируемом коде.
- **Hardware-facing изменения (кодоген, парсер, что проверяется только поведением реального МК)** не считаются завершёнными без HW-валидации (плата/осциллограф/логический анализатор/мультиметр) — исключение: EEPROM.
- **EEPROM НИКОГДА не тестируется на реальной плате** — риск затирания загрузчика.
- Комментарии/код/коммиты — на русском (как уже принято в репозитории).
