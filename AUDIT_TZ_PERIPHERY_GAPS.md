# ТЗ: пробелы периферии МИК32 относительно даташита

Дата: 2026-10-13. Ветка: `ccr-512de713-386cn3`.

## Методика

Каждый модуль сверен по трём источникам:
1. Текст даташита (прислан пользователем по частям, этот документ — его систематизация).
2. Реальный установленный HAL (`~/.platformio/packages/framework-mik32v2-sdk/hal/peripherals/Include/`) —
   не вендорный снэпшот в `docs/examples/`, который может быть устаревшим
   ([[feedback_hal_snapshot_vs_installed]]).
3. Текущая реализация конфигуратора: `schemas/*.json`, `parser/<модуль>/`, `codegen/project/*_contribution.cpp`, `gui/peripheral_tree.cpp`.

Статус "HAL есть" означает: закрываемый пробел — есть на что опереться в вендорном коде.
Статус "HAL нет" означает: регистровая работа без HAL-обвязки — заметно дороже и рискованнее,
обязательно требует отдельного проектирования и отдельной HW-валидации
([[feedback_hardware_validation_gate]]).

## Исправление по ходу аудита (важно!)

## Тир 1 — доработка существующих модулей конфигуратора

### USART — ✅ закрыто этой сессией
MSB/LSB, sync-режим, half-duplex, инверсии TX/RX, swap, RTS-режим, модемные
сигналы, DMA. См. `OVERNIGHT_SESSION_REPORT.md`.

### I2C
Текущий модуль: master+slave+auto-reset (`parser/i2c/i2c_parser.h`). ТЗ формальных
требований по I2C не содержит — схема построена по HAL.

- Второй собственный адрес + маска (`DualAddressMode`/`OwnAddress2`/`OwnAddress2Mask`) — HAL есть.
- General call (`GeneralCall`) — HAL есть.
- Clock stretching (`NoStretchMode`) — HAL есть (есть ворнинг в кодогене про NOSTRETCH без прерываний).
- Аналоговый + цифровой фильтр помех (`AnalogFilter`/`DigitalFilter`) — HAL есть.
- DMA — HAL есть (сейчас DMA реализован только для UART).

### Timer32
- Выбор источника тактирования — HAL даёт 6 вариантов, в конфигураторе — только `PRESCALER`.
- Маскирование прерываний по типам (4 типа) — сейчас либо все, либо ничего.
- Регистр `TIMER_CFG.MUX_TIM32_x_TIM1/TIM2` (sys_clk/hclk для TIM1, OSC32K/LSI32K для TIM2) — отдельный асинхронный источник тактирования по каналам, не покрыт вообще.

### Timer16
- Выбор источника тактирования — HAL даёт 7 вариантов, сейчас доступны только 2 (через поле `mode`).
- Триггер по фронту — хардкод `SOFTWARE`.
- Цифровой фильтр помех — хардкод `NONE`.
- Режим энкодера/декодера — не выведен вообще.
- **PWM-полярность/инверсия** (`Waveform.Polarity`, `HAL_Timer16_WaveformPolarityTypeDef`) —
  HAL поддерживает (`NONINVERTED`/`INVERTED`), сейчас хардкод `NONINVERTED`.
  *(Это исправленный вывод — в начале этого аудита я ошибочно сказал, что
  инверсии не существует вообще, из-за регистронезависимого грепа `Invert`,
  не найденного по шаблону `INVERTED` в верхнем регистре.)*
- `TIMER_CFG.MUX_TIM16_x` — 6-way выбор тактирования на каждый Timer16, не покрыт.

### SPI
- Прерывания (`HAL_SPI_InterruptEnable/Disable` реально существуют и используются
  внутри HAL для RX_FIFO_NOT_EMPTY/RX_OVERFLOW/TX_FIFO_NOT_FULL/MODE_FAIL) — конфигуратор
  работает только в режиме опроса, прерывания не настраиваются вообще. Единственный
  реальный закрываемый пробел по SPI.
- Порог RX FIFO, задержка SS/MOSI, программируемый режим детектирования старта —
  **тупик**: датащит описывает их на уровне IP-блока, но в установленном HAL этих
  полей физически нет ни в `SPI_InitTypeDef`, ни в вендорных примерах.

### Clock / PowerManager (PCC)
Текущий backend (`ClockConfig`, `renderSystemClockConfig()`) — 4 параметра из
~10 доступных в `PCC_InitTypeDef`:
- Калибровка HSI32M (`HSI32MCalibrationValue`, 0–255) — хардкод 128.
- Калибровка LSI32K (`LSI32KCalibrationValue`, 0–15) — хардкод 8.
- Источник тактирования RTC (`RTCClockSelection`/`RTCClockCPUSelection`) — хардкод AUTO/OSC32K.
- Маска включённых осцилляторов (`OscillatorEnable`) — хардкод ALL, нельзя выключить
  неиспользуемый генератор для экономии потребления.
- `ForceOscSys`/`Force32KClk` (принудительный выбор источника монитора частоты) — хардкод.
- **Тупик:** `WDT_CLK_MUX` (4-way тактирование сторожевого таймера) и `OSC32K_SM`
  (режим быстрого старта OSC32K) — нет соответствующих полей в `PCC_InitTypeDef`,
  только в сырых регистрах WU.

## Тир 2 — новые модули, HAL есть (закрываемо)

| Модуль | HAL-файлы | Комментарий |
|---|---|---|
| RTC | `mik32_hal_rtc.h/.c` | 24-часовой режим, календарь с учётом високосного года, будильник+прерывание, BCD. Сейчас не реализован вообще: ни схемы, ни парсера, ни узла в дереве. |
| CRC | `mik32_hal_crc32.h/.c` | CTRL/POLY/IFIFO/MUX/NOT-логика/TOT-TOTR побитовая перестановка, 8/16/32-битный доступ к регистру данных. Используется только вендорно, в конфигураторе не представлен. |
| EEPROM-контроллер | `mik32_hal_eeprom.h/.c` | Запись в несколько этапов через APB, чтение в 2/3 этапа, схема коррекции одиночных ошибок. Не реализован. |
| WDT (сторожевой таймер ядра) | `mik32_hal_wdt.h/.c` | 12-бит счётчик + 12-бит предделитель, защита от случайной записи, прерывание за 256 тактов до сброса. Не реализован. |
| ЦАП (DAC) | `mik32_hal_dac.h/.c` | 12-битный код, делитель `DACx_CFG.DIV` от APB_P. Не реализован. |
| АЦП (ADC) | `mik32_hal_adc.h/.c` | 12 бит, 8-канальный мультиплексор с дешифратором 3-в-8. Не реализован. |
| **CRYPTO** (исправлено) | `mik32_hal_crypto.h` | `Crypto_HandleTypeDef`: `Algorithm` (KUZNECHIK/MAGMA/AES), `CipherMode` (ECB/CBC/CTR), `SwapMode`, `OrderMode` (LSW/MSW). Три ядра, общий конечный автомат, флаги готовности для ПДП. Не реализован — но HAL есть, в отличие от первоначального вывода. |
| **OTP** (исправлено) | `mik32_hal_otp.h` | `OTP_HandleTypeDef.ReadMode` + функции `HAL_OTP_Write/Read/WriteTestColumn/WaitBSY` и т.д. 256 бит, 8×32 организация + тестовая строка. Не реализован — HAL есть. |
| **Датчик температуры (TSENS)** (исправлено) | `mik32_hal_tsens.h/.c` | Выбор тактового источника (`HAL_TSENS_ClockTypeDef`: sys_clk/hclk/…), одиночный/непрерывный режим измерения, прерывания по верх./нижн. порогу и по готовности (EOC). Не реализован — HAL есть. |

## Тир 3 — новые модули, HAL нет (регистровая работа, дороже и рискованнее)

| Модуль | Что нужно | Примечание |
|---|---|---|
| EPIC / контроллер прерываний | 32 линии, edge/level конфигурация по таблице источников | **Уточнение:** HAL частично есть — `mik32_hal_irq.h/.c` (`HAL_EPIC_MaskEdgeSet/Clear`, `MaskLevelSet/Clear`, `GetStatus`, `Clear`). Не "нет HAL вообще", а "HAL есть, но в конфигураторе не представлен" — фактически Тир 2, не Тир 3. |
| Сторожевой таймер шины (Bus Watchdog / AHB timeout monitor) | 3 монитора шины (EEPROM/SPIFI/APB_P-периферия) | Нет дополнительного HAL-файла; только флаги `HAL_EPIC_WDT_DOM3/SPIFI/EEPROM_MASK` в IRQ-контроллере для чтения состояния — сама настройка таймаутов регистровая. |
| Boot Manager | регистр `BOOT`, чтение режима загрузки Boot0/Boot1 | Только сырой заголовок `shared/periphery/boot.h`, HAL-обёртки нет. |
| Режимы энергопотребления (Активный/Пониж./Спящий/Стоп/Ожидание) | `PM->SLEEP_MODE`, `WU->STOP`, `WU->SYS_POWEROFF` | Нет HAL — только структура регистров в `shared/periphery/wakeup.h`. |
| Монитор питания (PVD, VCC/AVCC) | пороги `OVER_THRESH`/`UNDER_THRESH`, цифровой фильтр, тестовый режим | HAL даёт только `__HAL_PCC_PVD_CONTROL_CLK_ENABLE()` (включить тактирование блока) — сама настройка порогов регистровая (`shared/periphery/pvd_control.h`). |
| Схема переключения VCC/VBAT | регистр `POWER_SWITCH` | Нет HAL. |
| События пробуждения (`SYS_MASK`/`SYS_LEVEL`) | маски/уровни EXT_WU и RTC для выхода из Стоп/Ожидание | Нет HAL. |

## Рекомендация по порядку фиксов

Порядок по возрастанию риска/стоимости:
1. **Тир 1** — расширение уже работающих пайплайнов (I2C/Timer16/Timer32/SPI/Clock)
   — наименьший риск, модули уже валидированы на железе хотя бы частично.
2. **Тир 2** — новые модули с готовым HAL (RTC/CRC/EEPROM/WDT/DAC/ADC/CRYPTO/OTP/TSENS)
   — стандартный паттерн (schema+parser+codegen+GUI-узел) уже отработан 5 раз.
3. **Тир 3** — регистровая работа без HAL (Boot Manager/режимы питания/PVD/Bus Watchdog)
   — отдельное проектирование регистровых структур, выше риск ошибки, сложнее
   HW-валидировать (часть — аналоговые пороги, которые без специального
   оборудования не проверить).

Каждый пункт из Тир 1/2/3 при реализации проходит через обязательный
hardware-validation gate ([[feedback_hardware_validation_gate]]) — ни один пункт
не считается закрытым до проверки на реальной плате осциллографом/логическим
анализатором/мультиметром с указанием конкретной точки пробы.
