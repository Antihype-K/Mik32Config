## Источники истины и приоритеты
- ТЗ (ГОСТ, грантовое) > реально установленный HAL > docs/legacy архитектурный документ
- Datasheet/errata priority — errata = подтверждённые отклонения от даташита, обязаны определять воркэраунды
- HAL snapshot vs installed — docs/examples/ может быть новее установленного ~/.platformio/.../framework-mik32v2-sdk/, сверять перед использованием HAL-функций
- Сравнивать аргументы вызова при реверс-инжиниринге дизассемблера, не только тела функций
- Не угадывать полярность бит регистра без подтверждения (пример: PVD NRESETU/NRESETO)
- Проверять "нет HAL" перед тем как доверять аудиту — 3 ложных случая уже было

## Обязательные гейты
- Hardware validation gate — любая работа с кодогеном блокируется до HW-проверки с named probe point
- USER CODE markers обязательны в main.c при регенерации
- EEPROM — НИКОГДА не тестировать на реальной плате (2 инцидента 2026-10-14, затирает загрузчик)
- Чаще фиксировать прогресс в docs/implementations/ и TaskUpdate по ходу работы

## Важные технические находки
- HSI32M калибровка не точна по умолчанию — внутренний RC на calibration=128 искажает UART, внешний кварц чище
- Уровневое прерывание требует явного сброса флага на стороне периферии, не только EPIC
- HAL_Init()/EPIC gotcha — без HAL_Init() EPIC не тактирован, прерывание тихо не доходит до ядра
